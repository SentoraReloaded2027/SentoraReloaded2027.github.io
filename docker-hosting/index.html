Sentora 2027 / Docker app hosting

Free add-on: Docker Hosting

Host Docker Hub apps for your customers

Sell or give your customers their own apps, straight from Docker Hub: picked in the panel, started on a server of their own (a node), under their own domain with HTTPS. The containers never run on the panel's server.

How it works

  • Install the Docker Hosting add-on from Admin > Repo Browser in your Sentora 2027 panel.
  • Add a node: a fresh Linux server for the apps. One command on it installs rootless Podman, the Caddy web server and Sentora's node agent; it shows a key you paste into the panel. The panel shows its own code first, so the node knows it is talking to your panel.
  • Give your resellers and clients a share: how many apps, how much CPU, memory and disk, and which apps.
  • A customer picks an app, types a name under one of their own domains (for example status.example.com) and presses Start. The panel adds the DNS record if asked, the node downloads the image and starts it.
curl -fsSL https://raw.githubusercontent.com/RusTus/sentora-installers-2027/master2027/node/sentora2027-node -o sentora2027-node && sudo bash sentora2027-node

Run that on the new node as root. Nodes can be Ubuntu 26.04, Debian 13, AlmaLinux 10, Rocky Linux 10, Red Hat Enterprise Linux 10 or Fedora 45.

Every app starts behind a setup password, so only its owner can do its first setup (like making its administrator account). Then one switch opens it to the public.

Each customer kept apart

  • Rootless Podman runs the same images as Docker, without a root daemon: each customer's apps run under their own Linux user on the node, never as root, with no extra privileges.
  • CPU, memory and disk limits per app, held by the kernel; an app over its disk limit stops until it is given more room.
  • Apps listen on the node's 127.0.0.1 only, behind Caddy, which serves each one at its own address over HTTPS.
  • Apps reach the internet, but not your private network (other servers, routers, the panel by its local address) unless the administrator opens it for that customer. The cloud's metadata address stays closed for every app.
  • The panel never connects to a node: the node calls the panel. Every message is signed and sealed with the panel's and the node's own keys.

Updates, backups and warnings

  • App updates with one click, or by themselves at night: the new version is started and checked, and the old one comes back if it does not start.
  • App backups every night, with Back up now and Put this backup back, carried off the server by Sentora's off-server backup; an app can also move to another node with its data. (Offered when the off-server backup goes to a Sentora backup server.)
  • The node's own security updates, restarts and the node software's updates from the panel, or by themselves at night.
  • Needs a look: a node short of disk, waiting for updates or a restart, or gone quiet is shown at the top of the page, with the button that fixes it, and emailed to the administrators.

For hosting businesses

Docker app hosting fits the way Sentora already sells hosting. The administrator gives resellers a share; resellers give their clients part of theirs, or make Docker plans of their own (for example Small and Large) and put clients on them. Changing a plan changes every client on it, never below what a client already uses. With the Payment Plans add-on, the same sellers bill their clients through PayPal or Stripe.

Tested

Before a change is published, its tests start real nodes on Ubuntu 26.04, Debian 13, AlmaLinux 10, Rocky Linux 10 and Fedora 45 on GitHub, pull Uptime Kuma from Docker Hub, run it, read its limits from the kernel, check the setup password and that an app can not reach the node's own services, then restart and delete it. It has also run on a real AlmaLinux 10 node with SELinux enforcing. The add-on's own guide: the add-on repository's README.

Questions

Can I host Docker Hub images for my customers?

Yes. Docker Hosting runs apps from container images (Docker Hub, GitHub's ghcr.io, Quay and other registries) for your customers, each under their own domain with HTTPS. Uptime Kuma, Gitea, Vaultwarden and Nextcloud come ready to start; you add any other image you trust under Your own apps.

Does the node need Docker installed?

No. The node installer sets up rootless Podman, which runs the same images from Docker Hub without a root daemon. Each customer's apps run under that customer's own Linux user on the node.

Do the containers run on the panel's server?

Never. They run on separate servers, called nodes: Ubuntu 26.04, Debian 13, AlmaLinux, Rocky Linux or RHEL 10, or Fedora 45. The node calls the panel for its work, so nothing on the node has to be opened for the panel.

Can resellers sell Docker app hosting?

Yes. The administrator gives resellers a share (number of apps, CPU, memory, disk, and which apps), resellers give their clients part of theirs, or put them on Docker plans of their own. A client can never go past the share it was given.

Is Docker Hosting free?

Yes. It is a free add-on, open source under the GNU GPL v3 like the rest of Sentora 2027, installed with one click from Repo Browser in the panel.
