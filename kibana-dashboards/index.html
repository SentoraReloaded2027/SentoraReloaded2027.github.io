Sentora 2027 / Ready-made Kibana dashboards

Log Forwarder and the Elk node

Kibana, with the dashboards already made

Most ELK installs leave you with an empty Kibana and weeks of building dashboards. The Sentora 2027 Elk node comes with 34 of them, made for your panel's logs and for the systems around it, plus walls to put on a TV: one look tells you what is green, what is yellow and what needs you now.

Alerts in the panel, not only on a screen

The node checks every 5 minutes and the panel shows what needs a look as a notice, and mails the administrators: a website down, a certificate running out, a full disk, mail piling up, a burst of failed logins, an address attacking in several places, a failed Veeam job or a machine without a recent backup, a repository or datastore filling up, a Microsoft 365 sign-in from a new country, an account locked out, someone added to Domain Admins, a cleared security log, a vSphere host in red. Each alert links to its dashboard.

Each one is off until you switch it on with one command on the node, which then shows the steps for the other side.

Set it up

  • On the panel: install Log Forwarder from Admin > Repo Browser and open Advanced > Log Forwarder, Elk node.
  • On a new Ubuntu 26.04 server (at least 4 GB of memory), run the installer as root. It asks for the panel's address and shows the panel's code to compare with the page.
  • It ends with the node's key and the Kibana login: paste the key in the panel's Add the Elk node. The logs start coming, and the dashboards fill.
curl -fsSL https://raw.githubusercontent.com/RusTus/sentora-installers-2027/master2027/elk-node/sentora2027-elk-node -o sentora2027-elk-node && sudo bash sentora2027-elk-node

Kibana answers on the node's own address over HTTPS with its own login, which can read the logs but never delete them. sentora-elk-node update keeps the node and its dashboards up to date.

Secure by default

  • Elasticsearch's security is on; every user can do only its own job (Logstash writes, Kibana's login reads, the alerts read).
  • The node has its own small certificate authority. The panel and the node check each other's certificates; nothing secret is typed.
  • The firewall lets each source in from its own address only: the panel, the FortiGate, Veeam, each domain controller.
  • Readers of other systems use read-only accounts, and their certificates are pinned once you confirm them.

Tested

Every change installs a whole Elk node on GitHub and sends it the panel's logs and every source from stand-ins: FortiGate and Veeam lines, Microsoft Graph, Veeam's API, a Magento store, a domain controller through Winlogbeat's protocol and VMware's own vCenter simulator. It checks that each arrives and is understood, that every dashboard is there, that alerts fire, and that a stranger's certificate or address gets nothing in. Every dashboard is also looked at, light and dark.

Questions

Do I have to build the Kibana dashboards myself?

No. The Elk node installs 34 Kibana dashboards, made for Sentora's logs and for the other sources it reads (a FortiGate, Veeam, Microsoft 365, Active Directory, VMware vSphere, an online store). They work as soon as the logs arrive. You can still make your own, or copy one under another name and change it.

What happens to my own changes when the node is updated?

An update brings every Sentora dashboard back to its newest version. A copy saved under another name is yours and is never touched.

What does the Elk node need?

A server of its own (never the panel's) with Ubuntu 26.04, at least 4 GB of memory (8 GB or more is better) and room for the logs, kept 30 days unless you choose otherwise. It installs Elasticsearch, Logstash and Kibana 9 from Elastic's own packages.

Is it free?

Sentora 2027, the Log Forwarder add-on and the Elk node installer are free and open source under the GNU GPL v3. The Elastic stack is installed from Elastic's own packages and uses its free features.

Can it show my firewall, backups and Active Directory, not only websites?

Yes. Each is switched on with one command on the node: a FortiGate (sites people visit, VPN users, threats), Veeam Backup & Replication (jobs, machines, repositories), Microsoft 365 and Entra (sign-ins, Teams, mail, Microsoft's service health), Active Directory (logons, lockouts, admin group changes, through Winlogbeat on each domain controller) and VMware vCenter (hosts, VMs, datastores).
