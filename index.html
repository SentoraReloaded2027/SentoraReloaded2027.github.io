This is not the old panel

Rebuilt, not patched

Sentora 2027 kept what was good about Sentora, its Dryden framework and the way the panel works, and went over everything else with a fine-tooth comb. Nearly every file of the old panel was reworked or replaced, the framework was built out for today's PHP, and module after module was rewritten, tested and rewritten again.

The old panel's known bugs and security holes are gone, fixed or replaced along with the code they lived in. What's left is a panel made for PHP 8.5, MySQL 8.4 and today's Linux, with every change written down in the changelog.

97%of the old panel's files reworked or replaced (212 of 218)
3⁄4of today's code is new: about 68,000 of 92,000 lines
2.6×the Dryden framework, kept and built out (7,600 lines then, 19,800 now)
470+changes in the changelog; 55 modules, 16 of them new

One command, every Linux

Installed in ten minutes or so

On a fresh server, as root. The installer finds out which Linux it runs on, fetches that system's installer and checks it against its SHA-256 before running it.

curl -fLo sentora2027-install https://github.com/RusTus/sentora-installers-2027/releases/download/current/sentora2027-install && bash sentora2027-install

Answer a few questions

The panel's name, your email and time zone. Every password it makes is shown once and saved in /root/passwords.txt.

2 · restart

Restart the server

Every service starts at boot by itself. Five minutes later the panel's daemon has done its first run.

3 · check

Prove it works

sentora-post-install-check looks at about a hundred things; sentora-smoke-test runs 26 real steps, from FTP upload to mail delivery.

Coming from Sentora 1.0 or 2.0?

Bring everything over

Two commands move a whole old Sentora server, on Debian, Ubuntu or CentOS, into Sentora 2027. Reading the old server changes nothing on it.

On the old server, as root

wget https://github.com/RusTus/sentora-installers-2027/releases/download/current/sentora-migrate-export
bash sentora-migrate-export --to-server <new server>

On the new server

sentora-migrate-import /root/sentora-export-<server>-<date> --all --yes
  • Accounts, resellers and packages, matched by name, made here when missing
  • Domains, sub-domains, parked domains and their DNS records
  • Websites and databases, with every database user
  • Mailboxes with all their mail, filters and out-of-office replies, and webmail address books
  • Straight over SSH when the old server has no room; checksums on every file
  • A dry run first shows what will happen; then one account at a time, or all at once
  • Old sites keep running on PHP 7.1 until you move them to PHP 8; old .htaccess lines fixed, after asking

Fully automated: no unzipping, no SQL, no permissions

Updates straight from the current release

As soon as a release is published on GitHub, every panel knows within the hour and shows it. One click in Admin > Panel Update, or one command, and it updates itself. The system's own security updates install by themselves every day.

  • Nothing to do by hand: new files in, old ones out, every permission set, new modules registered
  • Databases updated for you: the panel's own, Roundcube's and Matomo's
  • Checked against its SHA-256 before anything changes, and the server checked after
  • A backup first, every time (the last five are kept)
  • Rollback in one step if you want the version before
  • phpMyAdmin, Roundcube and Matomo come along with the panel
  • Extra PHP versions get their own Update button when a newer build is ready

Secure by default

Nothing switched off to make it work

The old way was to turn off whatever got in the way. Sentora 2027 works with every guard on.

SELinux & AppArmor
On, on every Linux system. The services the system confines (BIND and ClamAV everywhere, MySQL and ProFTPD too on Ubuntu) run confined, with Sentora's paths added to their profiles, never with the profiles disabled.
Web firewall
ModSecurity with OWASP CRS 4.25.2, switched on with the Web Hardening add-on: off, watch only, or blocking.
Account isolation
Every hosting account has its own Linux user, PHP-FPM pool and closed folder. One site can't read another.
Passwords
Mailboxes in SHA-512 crypt, FTP as hashes only, MySQL passwords kept encrypted. No plain copies anywhere.
TLS
Modern connections only. TLS 1.1 and old CBC ciphers are refused on the web and for mail.
fail2ban
Jails for the panel, phpMyAdmin, SSH, mail and FTP logins, on from the first boot.
Updates
The system's security updates install themselves every day; the panel updates with one click, and can roll back.
Tested releases
Five Linux systems installed from scratch and smoke-tested on every release. Nothing is published unless all pass.

Not just some app dropped on Linux

Hardened, then proven

Every server is set up the careful way, checked on the spot, and every release is installed and attacked on fresh systems before anyone gets it. Whatever the tests found was fixed, not hidden.

1 · at install

Hardened from the start

  • Every download checked against its SHA-256: the installer itself, PHP builds, SOGo; EPEL only with Fedora's signature
  • Random passwords for every service, kept in a file only root can read
  • SELinux labels and AppArmor rules written for Sentora's folders, so nothing has to be switched off
  • MySQL, memcached and SOGo listen on the server only; unneeded consoles such as Cockpit switched off
  • Settings files readable only by the service that needs them; nothing writable by everyone
  • Package mirrors read over HTTPS when a network tampers with plain downloads
  • Automatic security updates on from the first day
2 · on your server

Checked on the spot

  • sentora-post-install-check: about a hundred checks, from open ports and file permissions to TLS and stored passwords
  • Which services run confined by SELinux or AppArmor, and anything refused since the start
  • sentora-smoke-test: 26 real steps (a client, site, FTP upload, mail sent and delivered, a virus and spam refused, database, backup and restore)
  • Account isolation tried for real: one account must not reach another's files
  • Sites may use only their own PHP; the panel's PHP runs only the panel's own scripts
  • Two-factor login, login lockout and fail2ban watching the panel, mail, FTP and SSH
3 · before every release

Proven, every time

  • Five Linux systems installed from scratch, restarted, checked and smoke-tested on GitHub; nothing is published unless all pass
  • AppArmor in enforce mode during those tests: any refusal fails the release
  • Real attacks on a hosted site (cross-site scripting, SQL injection, path traversal) must be stopped by ModSecurity
  • New add-ons get a security review and their own tests before they're offered
  • Security watch every week: known exploited holes (CISA's list) and new releases of everything Sentora ships
  • Tried on real machines too: Ubuntu, Debian, AlmaLinux, RHEL, Fedora and Windows 11
~100checks on every server 26real steps in the smoke test 5systems tested per release 0guards switched off

So you can rest easy. Sentora 2027 is built and tested like the server software it is, with the time taken to keep your websites, mail and your clients' information safe.

What's inside

Web

Apache with PHP 8.x per site, extra versions from 7.1 to 8.5, and Let's Encrypt certificates with Sencrypt.

Mail

Postfix and Dovecot, Roundcube webmail, SOGo calendars, contacts and ActiveSync, with SpamAssassin and ClamAV.

Databases

MySQL or MariaDB, managed from the panel, with phpMyAdmin.

DNS & FTP

BIND for your zones; ProFTPD over TLS with per-account logins.

Stats

Matomo analytics, built in.

Backups

Per account, restored with one click, and copied off the server if you want.

Server Monitor

CPU per core, memory, network, disks and every process, live.

Resellers

Packages, clients, your own branding, and an API for automation. Bill your clients with Payment Plans: prices per package, invoices, PayPal or Stripe.
